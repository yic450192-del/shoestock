## 2026-09-23 · 阶段一：选型 + 骨架 + 数据层（M0 ~ M1）

### 1. 需求与技术约束的重新确认

原始诉求："不想为了做这个 app 再学一套移动端语言和架构"。

这个约束直接否掉了原生 Kotlin + Compose 的路线。重新比对了四条路径后选定
**Capacitor 8 + Vue 3** —— 它让你已有的 Vue 3 / TypeScript 能力直接迁移到安卓，
唯一新增的技能点只有 `npx cap sync`、`npx cap open android` 三条命令。

决策依据沉淀在 `docs/00-技术选型决策书.md`。

### 2. 开源项目调研

在 GitHub 上核到四个真实可参考的项目，最接近的是
[lukaszwatral/ShelfMate](https://github.com/lukaszwatral/ShelfMate)
（Vue 3 + Capacitor + SQLite + Kysely，离线优先，FTS5 全文搜索）。
本项目借用了它的分层思路（`db/repositories` + `services` + `views`），
但没有复用代码 —— 它的领域是家庭储物，实体为 Item/Place/Category，没有 SKU 矩阵。

其余三个（Java 的 Stockify、Kotlin 的 IMS、实体轮胎店在用的 zebra-inventory-system）
主要用于印证业务边界：低库存告警、版本化迁移、进货销售账单这些是该有的功能。

### 5. 踩到并记录下来的坑

- **npm install 中途被 Windows 文件锁打断**（esbuild 的 `install.js` 同步 spawn `node.exe` 返回 EBUSY），
  导致依赖树残缺，之后所有 `npm install` 都报 `Invalid Version:`。
  解法：`npm install --ignore-scripts` 绕开安装脚本，依赖照样落位（esbuild 的平台二进制是独立可选包，不受影响）。
- **Vite 8 与 vitest 的 `defineConfig` 类型不互通**，混用会产生无法消除的插件重载冲突。
  解法：`vite.config.ts` 只从 `vite` 导入，去掉 `test` 字段 —— vitest 默认的 include 已覆盖 `src/**/*.spec.ts`。
- 构建时关于 jeep-sqlite 引用 `crypto` 的警告**可以安全忽略**：
  它实际是先判断 `globalThis.crypto.getRandomValues` 是否存在再使用，
  `require("crypto")` 那行只在不走的 Node 分支里。
- 写 `stockService.ts` 时一度把手动编辑的路径写成了占位 hack，
  违反了"执行入口唯一"的自定规则，已改成在 `StockCommand` 上加 `skuId` 直达通道，
  精确操作和模糊匹配共用同一个 `confirmApply` 写库。

## 2026-09-23 · 阶段二：语音链路 + 备份（P4 + P5）

### 1. 推翻了上一轮的百度语音方案

上一阶段定的方案是「录音插件 + 百度短语音识别 REST」。动手前核到两个致命问题：

- **`@capacitor/http` 已经弃用**（npm 上最新只有 `0.0.2`），Capacitor 8 里没有官方的原生 HTTP 通道。
- **CORS 绕不过去**：Capacitor Android 的 WebView origin 是 `https://localhost`，
  从这里直接 `fetch` 百度接口会被同源策略拦死，百度也不会返回 CORS 头。
  要接云端识别就得额外引入原生 HTTP 通道或写 Java 插件，与"搭建全靠 AI、尽量少碰原生"的目标冲突。

改选 **`@capgo/capacitor-speech-recognition` 8.3.2**：系统原生识别，免费、免 key、可端侧运行，
主版本与 Capacitor 8 对齐。代价是部分精简版国产 ROM 没有语音引擎会不可用 ——
所以 `available()` 探测 + 手动输入通道是必需的，不是可选项。

同时删掉了 `@capgo/capacitor-audio-recorder`（语音识别插件自带麦克风，录音插件已是冗余），
项目里也不再有 `.env` 要填。

### 4. 修掉的两个真实缺陷（不是"顺手优化"）

- **`nlu.ts` 听不懂「42码卖了3」**：动作词和数字之间夹了「了」，正则就匹配不上，
  数量识别失败 → 默认成 1 → 而那个「3」会残留进 `productHint`，
  导致 `LIKE '%空军一号 3%'` 匹配落空。
  修法是动作词后允许 `[了着过]`，并在清理款名时删掉"独立成块"的残留数字
  （保留 `aj1` 这类款名自带的数字，因为删了反而让匹配更宽松，不影响命中）。

- **`stockService.resolveWith()` 会绕过确认卡直接写库**，违反硬约束第 5 条。
  这个函数当时没有任何调用方，属于"留着迟早出事"的隐患，已删除。
  正确做法是候选被选中后带上 `skuId` 重新调 `applyCommand()`，让确认卡再走一遍。
