# 技术选型决策书 · 鞋子库存管理器 APK

> 目标：一个只在手机上运行、能管理鞋子的分类 / 数量 / 码数、支持语音和搜索改数据的安卓应用。
> 约束（来自 Violet）：**不想学新的移动端语言或架构**；搭建阶段由 AI 完成；本人只拍重大决策。
> 日期：2026-09-23

---

## 一、先回答最核心的问题：我到底要不要学新东西？

**不要。** 你手上已经有两套能产出 APK 的技术：Java 和 Vue 3。走 Kotlin + Compose 那条路才需要学新语言，而那条路对你这个项目是**多余的**。

理由很简单：这个 app 的技术难点在**数据建模**和**语音链路**，不在 UI 渲染性能。它不是一个要跑 60fps 动画的应用，而是一个表单 + 列表 + 语音输入的工具。用 WebView 容器（Capacitor）承载 Vue 3 完全够用，而让 APK 能用上原生 SQLite 和麦克风，靠的是 Capacitor 插件而不是新语言。

**你唯一需要新增的技能点只有三条命令**（`npx cap sync` / `npx cap open android` / 在 Android Studio 里点 Build），总共不超过半小时。

## 二、候选方案对比

| 方案 | 你要学什么 | 离线 SQLite | 语音能力 | AI 能否全程代工 | 结论 |
|---|---|---|---|---|---|
| **A. Capacitor 8 + Vue 3**（推荐） | 几乎无（3 条命令） | ✅ 原生 SQLite | ⚠️ 录音插件 + 云端 ASR | ✅ 纯 CLI，全可自动化 | **选它** |
| B. uni-app + Vue 3 | 少量（HBuilderX 体系） | ✅ 需插件市场 UTS 插件 | ✅ 官方 Speech 模块 | ❌ 大量 GUI 操作 + 云打包，AI 难以自动化 | 备选 |
| C. 原生 Kotlin + Compose | **Kotlin + Compose + Jetpack**（大） | ✅ Room | ✅ 原生 SDK | ✅ | 排除：学习成本与目标不匹配 |
| D. Flutter | Dart（新语言） | ✅ sqflite | ✅ | ✅ | 排除：同样要学新语言 |

**为什么 B（uni-app）排在第二而不是并列：**

uni-app 确实也能用 Vue 语法，而且官方内置了百度语音识别模块（`plus.speech`）——这点是它比 Capacitor 强的地方。但它有两个硬伤对"AI 全程代工"致命：

1. **必须依赖 HBuilderX 或云打包**。uni-app 官方自己承认：App 端用 SQLite 和语音都「须勾选自定义调试基座」，而生成自定义基座要走云端打包。这是一个**图形界面 + 云端队列**的流程，我敲命令行替你做不了。
2. **语音同样依赖第三方 appid 配置**，且官方文档明确注明讯飞方案「有识别次数限制，推荐优先使用百度」。

Capacitor 全部流程在命令行：`npm install` → `npx cap sync` → `npx cap open android` → 点 Build。这也是它被选为主方案的根本原因。

## 三、调研证据：真实存在的同类开源项目

不是 CSDN 付费源码包，以下是 GitHub 上真实可 clone 的项目（2026-09-23 核到）：

| 项目 | 技术栈 | 匹配度 | 用途 |
|---|---|---|---|
| **[lukaszwatral/ShelfMate](https://github.com/lukaszwatral/ShelfMate)** | **Vue 3 + Vite + Capacitor + SQLite + Kysely，离线优先，FTS5 全文搜索** | ⭐⭐⭐⭐⭐ | **主参考**：几乎就是我们要的架构（现已能把条形码/NFC 也一并借鉴） |
| [Varadha9/Stockify](https://github.com/Varadha9/Stockify) | Java，离线优先，小零售库存 + 扫码 + 低库存告警 | ⭐⭐⭐⭐ | 业务建模参考：它的"低库存告警"就是我们需要的断码预警 |
| [MENT0Z/IMS](https://github.com/MENT0Z/IMS) | Kotlin，离线优先，含进货/销售/账单/备份 | ⭐⭐⭐⭐ | 业务边界参考：看看别人把哪些功能算作"库存管理"必需 |
| [beck-bargas/zebra-inventory-system](https://github.com/beck-bargas/zebra-inventory-system) | Kotlin + SQLite + 版本化迁移，**实体轮胎店在用** | ⭐⭐⭐⭐ | 迁移策略参考：它是"给实体门店用"的真实样本（轮胎的规格 ≈ 我们的码数） |

**ShelfMate 给我们的直接收获**（已吸收进本项目结构）：

- 目录分层：`db/models` + `db/repositories` + `services` + `views`
- 用 SQLite **FTS5** 做全文搜索，而不是 `LIKE '%keyword%'`
- SQLite 作为唯一数据源，**不依赖任何网络**

我不复用它的代码（它的领域是"家庭储物"，实体关系是 Item/Place/Category，没有 SKU 矩阵），但**架构照搬**。

## 四、推荐方案（已核实版本，2026-09-23）

### 技术栈

```
Vue 3.5.43  +  Vite 8.3.0  +  TypeScript
+ Vant 4.10.2            (移动端 UI 组件库，省掉 80% 样式代码)
+ Pinia                  (状态管理)
+ Capacitor 8.5.2        (原生容器)
+ @capacitor-community/sqlite 8.1.1     (原生 SQLite / Web 端 jeep-sqlite 降级)
+ @capgo/capacitor-audio-recorder 8.2.9 (麦克风录音，免费)
+ 百度短语音识别 REST API               (音频 → 文字)
+ 本地规则解析                          (文字 → StockCommand)
```

> **版本对齐是 Capacitor 生态第一大坑**：插件主版本号必须与 Capacitor 主版本号一致。上面三者均为 8.x，已验证。

### 为什么语音走"录音 + 云端 REST"而不是"原生 SDK"

| 做法 | 问题 |
|---|---|
| 系统自带 `SpeechRecognizer` | 国内 ROM 大多没有 Google 引擎，直接回调失败。**不能用** |
| 讯飞/百度原生 SDK | 要手动放 `.jar`/`.so`、声明 nativeplugins 目录结构、配 `android.json` 权限，漏一步就是 `UnsatisfiedLinkError` |
| **录音插件 + REST API**（选它） | 只需一次 HTTP POST，无原生 SDK，无需 HBuilderX，密钥填一行配置 |

代价：**语音环节需要联网**（你已确认可接受）。数据的增删改查全程离线，不受影响。

### 数据流

```
手机麦克风
  → @capgo/capacitor-audio-recorder  录音得到音频文件
  → 百度短语音识别 REST              得到一句中文文本
  → services/nlu.ts 本地规则解析      得到 StockCommand {动作, 款名, 颜色, 码数, 数量}
  → services/stockService.ts          模糊匹配 SKU → 校验 → 返回预览
  → 确认卡 UI（必须人工确认）
  → SQLite 写 sku.stock + 插 stock_log
```

## 五、需要你拍板的三件事

### 决策 1：要不要一口气兼容微信小程序 / H5？

- **只做 APK**（推荐）：专注、快两周出成果。
- **顺便出小程序**：Capacitor 做不到，需要换 uni-app 或额外套 Taro。卖鞋场景确实常用微信发图片、开单，**但建议二期再议**。

### 决策 2：语音识别用哪家的 REST API？

三家的短语音识别都有免费额度，中文识别率都在可用区间：

| 厂商 | 免费额度 | 特点 |
|---|---|---|
| **百度**（推荐） | 个人认证后额度足够自用 | 文档成熟，短语音 REST 最简单 |
| 讯飞 | 有额度但限制更细 | 中文识别第一梯队，SDK 体积大 |
| 阿里 | 有额度 | 偏 Web API 形态 |

**建议你做一件事**：自己去申请一个百度 AI 开放平台的 key（需要你的手机号实名，这是唯一我替不了的步骤），把 appId / apiKey / secretKey 三串给我，我接进去。

### 决策 3：这个项目的最终用途？

这会直接影响我怎么写：

- **给店里真用** → 我会偏保守：冗余校验、备份导出优先。
- **同时当求职项目**（猜是这种）→ 我会在架构上做出可讲的亮点：离线优先、事件溯源式流水、语音指令的可测试性。**这个我默认按"两者兼有"来处理**，除非你否定。

## 七、已知风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| WebView 在低端机上列表卡顿 | 款式多时滚动掉帧 | Vant List 自带虚拟滚动；超过 2000 条再做分页 |
| SQLite 插件要求 Gradle JDK 21 / AGP 8.7.2 | 编译报错 | Android Studio 2026 版默认已带；写在 README 里 |
| 百度 key 硬编码在 App 里会被反编译看到 | 额度被盗用 | 自用可接受；二期可加一层自己的转发（那时你的 Spring Boot 就派上用场了） |
| 语音误识别导致库存改错 | **账目崩** | 强制确认卡 + stock_log 流水可回滚（已实现，不可绕过） |
